# scMultiomeBench

Code and processed results for a benchmark of single-cell RNA + ATAC integration methods,
published in *Genomics, Proteomics & Bioinformatics* (GPB).

## 1. What this is

This repository contains everything used to produce the figures and tables of the benchmark:
preprocessing, per-method integration runs, metric computation, and plotting. The benchmark asks how
well integration methods align **independently sequenced (unpaired) scRNA-seq and scATAC-seq** — the
setting in which the two modalities come from different cells, so no cell-to-cell correspondence
exists to lean on. Fourteen integration methods are benchmarked across six datasets; the primary
PBMC 3k benchmark extends to 23 method configurations, and the BMMC dataset adds six batch-aware
variants. Methods are scored on three axes: preservation of biological diversity, reduction of the
omics gap, and cross-modality alignment.

### Datasets

| Directory | Dataset | System | Source and access |
|---|---|---|---|
| `datasets/pbmc3k` | PBMC 3k | Human PBMC | 10x Genomics public multiome — open |
| `datasets/pbmc10k` | PBMC 10k | Human PBMC | 10x Genomics public multiome — open |
| `datasets/pbmc_parse` | Parse PBMC | Human PBMC | Parse Biosciences Evercode WT Mini v3 public dataset — open |
| `datasets/bmmc_d1` | BMMC | Human bone marrow | GEO GSE194122 — open |
| `datasets/brca` | Breast cancer | HTAN WUSTL | dbGaP **phs002371.v3.p1** — **controlled access**. Samples HT243B1-S1H4 (Synapse `syn53214720` RNA / `syn53215789` ATAC) and HT263B1-S1H1 (`syn53214683` / `syn53215774`, paired training sample) |
| `datasets/rms` | Rhabdomyosarcoma | Patient-derived tumour | GEO **GSE209784** — open, generated by the authors |

### Composite score

The composite score averages six metrics for unpaired data — `ks_celltype_mean` and `asw`
(biological diversity preservation), `omics_asw` and `ks_inter_celltype_mean` (omics gap reduction),
`average_accu` and `peakdist_adj` (cross-modality alignment). Paired (true multiome) data adds three
same-cell metrics — `ks.statistic`, `ari`, `ami` — for nine in total; these are undefined for
independently sequenced datasets, which is why some figures show a 9-metric matrix and others a
6-metric one. KNN label transfer uses k = 10, cosine distance, distance-weighted.

## 2. Repository map

```
scMultiomeBench/
├── config/               Path configuration (config.sh, config.yaml, config.R) — see Quick start
├── envs/                 Conda environment exports + build scripts (see section 6)
├── common/               Vendored helpers shared across datasets (see common/README.md)
├── 00_download/          One fetch/verify script per dataset; accessions are in DATA.md
├── datasets/             One directory per dataset; the four-stage pipeline lives here
│   ├── pbmc3k/           primary benchmark, 23 method configurations (+ 05_geneactivity_archr)
│   ├── pbmc10k/
│   ├── pbmc_parse/
│   ├── bmmc_d1/          (+ 05_crosssite, 06_s1d1_paired)
│   ├── brca/             (+ 05_macrophage_subsample)
│   └── rms/
├── summary/              Cross-dataset analyses (Fig 7, Fig S2A, Fig S13)
└── pipeline/             Numbered driver scripts recording the execution order
```

`results/` (merged final tables, metric tables, per-method latents, ground-truth labels — see
`results/README.md`) is not published in this repository; it is **available directly from the
authors on request**.

Inside each dataset: `01_preprocess → 02_methods/<Method> → 03_metrics → 04_figures`. Numeric
prefixes give the run order; `05_`/`06_` directories are follow-up analyses branching off the main
chain. A `<script>_sub.sh` file is the original LSF submission wrapper for the script of the same
name — the record of how it was run and resourced.

## 3. Quick start

```bash
git clone https://github.com/chenlab-sj/scMultiomeBench.git
cd scMultiomeBench

# Set your paths. config.local.sh is gitignored and is the only file you edit.
cp config/config.local.sh.example config/config.local.sh
$EDITOR config/config.local.sh          # set DATA_ROOT and PROJECT_ROOT
```

`config/config.sh` defines `DATA_ROOT`, `PROJECT_ROOT`, `BENCHMARK_FUN_DIR` and `PUBLISHED_REF`,
mirrored in `config/config.yaml` (Python) and `config/config.R` (R). Shell scripts pick the config
up automatically; `.py` and `.R` scripts carry literal placeholder paths (`/path/to/data/...`,
`/path/to/multiomeBench/...` — the latter means your checkout root) that you edit at the top of the
file before running one by hand.

## 4. Reproducing a figure

Rerunning the integration methods is not required to redraw any figure. Every metrics-matrix figure
(Fig 2B, 5A, S2C, S6, S11, S12, and the Fig 6A panel) runs in **single-file mode by default**: the
script loads a merged table from `results/` (`fig2b_matrix.csv` / `metrics_matrix.csv` /
`fig6_scores.csv`) and renders the published figure directly — verified to round-trip identically.
Set `REBUILD_MATRIX=1` to instead rebuild the merged table from the per-metric tables plus the
reference tables of the original run. `results/` is not published in this repository — it, and the
per-metric/reference tables, are **available directly from the authors on request**.

**`FIGURES.md` maps every manuscript and supplementary panel to the script that generates it and
the inputs it needs.** Start there. `DATA.md` documents every raw-data source and access route.

## 5. Rerunning the pipeline

The five numbered drivers in `pipeline/` record the full execution order
(`00_download → 01_preprocess → 02_run_methods → 03_compute_metrics → 04_make_figures`); they
default to `DRY_RUN=1`, which prints commands without executing anything. Stage 02 is the expensive
part (some methods take days on a GPU node). See `pipeline/README.md`.

## 6. Environments

There is no single environment: the 14 methods carry mutually incompatible pins. `envs/conda/`
holds, per environment, a portable `<name>.yml` (build from this), a `<name>.full.yml` exact-version
record, and a `<name>.pip.txt` pip freeze. Five methods (MIDAS, MIRA, MaxFuse, Multigrate,
scButterfly) need hand-pinning — build those with `envs/conda/setup_*.sh` and check with
`verify_*.sh` instead of a plain `conda env create`. R package versions for the `seurat4`
environment (Seurat/Signac prep, Seurat CCA/WNN, Conos, peak similarity, plotting) are recorded in
`envs/R/package_versions_seurat4.txt`.
